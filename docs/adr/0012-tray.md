# 12. The notification area while the taskbar is hidden

- Status: Accepted
- Date: 2026-10-15

## Context

Hiding the taskbar (ADR 0006) also hides what lives on it besides app buttons: the notification area (other
apps' tray icons), the clock, quick settings and notifications. Windows has no public API to read or host
other apps' tray icons: `Shell_NotifyIcon` talks to whichever window is the taskbar. Rule 6 forbids
undocumented shell internals, and ADR 0006 forbids windows with Explorer's class names. Overlay badges,
progress and custom jump-list tasks (`ITaskbarList3`, `ICustomDestinationList`) are write-only for apps too.

The spike (M3 step 0, Windows 11 26H1, ARM64, Explorer's taskbar hidden with `SW_HIDE` and auto-hide on):
- `ShowWindowAsync(Shell_TrayWnd, SW_SHOWNA)`, then `SetForegroundWindow` after a click on our island:
  Explorer slides the taskbar in within a second; it stays while it has focus (watched for 5 s).
- Win+N (notifications and calendar) and Win+A (quick settings) open their flyouts with the taskbar hidden.
  Win+T gives the hidden taskbar the focus without showing it, so it doesn't trip the re-show breaker.

## Decision

**"Peek": the dock brings the real taskbar forward on request.**
- While Harbor hides the taskbar, the island ends with a tray button (an upward chevron; UI Automation: a
  button, "Show taskbar"; no menu). Clicking it shows the hidden `Shell_TrayWnd` (`SW_SHOWNA`: auto-hidden,
  off the screen but for a sliver) and gives it the foreground, from the UI thread that took the click;
  Explorer slides it in, tray icons, clock and all. (The foreground alone doesn't make Explorer show a hidden
  taskbar: the spike showed it first, and the real check without that saw nothing. Through UI Automation
  Windows may refuse the foreground; the taskbar then stays auto-hidden until the peek ends.)
- `GuardPolicy` gets a "peeking" input. While it is set, Explorer showing the taskbar is neither re-hidden
  nor counted toward the re-show breaker. The peek ends when Explorer slides the taskbar back out, which it
  does once the focus leaves the taskbar and its flyouts: a second after the guard (checking every 250 ms)
  last saw at least half of it on its monitor, the dock hides its windows again (`SW_HIDE`; auto-hide stayed
  on). A peek the taskbar never answered ends after 3 s. The panic hotkey, hiding off, a lost link and every
  restore path work as before while peeking, and end the peek.
- Peeking only ever shows the taskbar, the safe direction: a mistake leaves it visible, never lost. Its
  restore-path tests come first: panic, Harbor Shell gone, dock crash and dock hang, each while peeking.
- The keyboard routes need nothing from Harbor: Win+N and Win+A keep working (README).

## Alternatives considered

- **A notification area of our own**, by registering a window as the taskbar to receive `Shell_NotifyIcon`
  (what ManagedShell-based shells do): undocumented, fights Explorer, and needs Explorer's class names.
- **Reading Explorer's tray through UI Automation** and drawing it in the dock: scraping (rule 6); breaks
  with Explorer updates, and clicks wouldn't reach the apps the way Explorer sends them.
- **Leaving part of the taskbar visible** (a region or clip on Explorer's window): changes another process's
  window in ways Windows doesn't document.
- (M4, ADR 0015: the dock injects keys that are not the Windows key: an unassigned mask key, the island's
  hotkey, and Ctrl+Esc for Windows' Start. The concern below is about synthesizing Win itself.)
  **Buttons that type Win+N or Win+A for the user** (`SendInput`): synthesizing the Windows key can leave it
  stuck or open Start; the keys already work.

## Consequences

- Tray icons, the clock and quick settings stay in Windows' own UI, one click away; Harbor has no tray code
  to break.
- Badges, progress bars and jump lists don't appear on the dock (no public read API).
- The breaker can't see Explorer fighting Harbor while the user peeks; peeking ends when Explorer slides the
  taskbar away, so it can't last unnoticed.
- The tray button takes a place on the island while the taskbar is hidden (it keeps the last place; the "…"
  button comes before it).
